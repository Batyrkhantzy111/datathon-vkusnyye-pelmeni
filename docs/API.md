# API

Реализация — `service/app.py`. Схема ответа соответствует разделу 10 ТЗ; дополнительные поля помечены ниже.

- **Базовый адрес:** публичный адрес сервиса (см. [README.md](README.md#адреса-и-ключ)); на хосте — `http://127.0.0.1:8000`.
- **Ключ:** заголовок `X-API-Key: <ключ>` для `/api/v1/analyze` и `/api/v1/jobs/{job_id}`. Ключ хранится на хосте в `~/forte/service/api_key.txt`, команда передаёт его жюри.
- **Кодировка ответов:** JSON, UTF‑8; тексты на русском.

## Эндпоинты

| Метод | Путь | Ключ | Назначение |
|---|---|---|---|
| POST | `/api/v1/analyze` | да | загрузить видео: `multipart/form-data`, поле `file`, расширение .mov или .mp4 (также .m4v, .qt), до 200 МБ |
| GET | `/api/v1/jobs/{job_id}` | да | статус задачи и результат |
| GET | `/api/v1/types` | нет | реестр типов нарушений и норм из `pipeline/norms.json` (то же отдаёт `/ui/types`) |
| GET | `/api/v1/health` | нет | состояние сервиса и очереди |
| GET | `/` | нет | веб‑интерфейс |
| POST | `/ui/analyze`, GET `/ui/jobs/{job_id}`, GET `/ui/jobs/{job_id}/video` | нет | те же обработчики для веб‑интерфейса (FAQ 27) и исходное видео для плеера |

### POST /api/v1/analyze

```bash
curl -X POST "$URL/api/v1/analyze" -H "X-API-Key: $KEY" -F "file=@video_017.mov"
```

Ответ `200`:

```json
{"job_id": "99c7837d0400", "status": "processing"}
```

Перед ответом сервис сохраняет файл, читает его через ffprobe и декодирует ffmpeg по одному кадру в начале и в середине видео (каждый — не дольше 5 с). Нечитаемое видео отклоняется сразу (400), а не через несколько минут.

### GET /api/v1/jobs/{job_id}

```bash
curl -H "X-API-Key: $KEY" "$URL/api/v1/jobs/99c7837d0400"
```

**В обработке** (`status: processing`):

```json
{"job_id": "99c7837d0400", "status": "processing", "progress": 0.5,
 "stage": "Действия с деньгами и документами", "queue_position": 0,
 "filename": "X-15.mov", "created_at": 1792284485.24, "video_duration_sec": 20.87}
```

- `progress` — от 0 до 0.99 во время обработки;
- `stage` — текущий этап, например «В очереди», «Загрузка моделей», «Декодирование видео», «Анализ людей, сцены и действий», «Действия с деньгами и документами», «Люди в кабинете», «Проверка событий: уход кассира, вход в кабинет», «Проверка правил», «Кадры-доказательства»;
- `queue_position` — место в очереди (1 — следующая), 0 — задача уже обрабатывается.

**Ошибка обработки** (`status: failed`):

```json
{"job_id": "99c7837d0400", "status": "failed", "error": "RuntimeError: ...", "processing_sec": 3.1}
```

**Готово** (`status: done`). Пример — результат анализатора для открытого ролика X‑15 (`~/forte/cache/results/X-15.json`); `image_base64` и цитата нормы сокращены:

### Поля результата

| Поле | ТЗ | Описание |
|---|---|---|
| `verdict` | да | `violation`, если найдено хотя бы одно нарушение, иначе `no_violation` |
| `violations` | да | список нарушений, пустой при `no_violation`; не больше одного на тип, отсортирован по убыванию `confidence` |
| `violations[].type` | да | название типа из `pipeline/norms.json` ([TYPES.md](TYPES.md)) |
| `violations[].timecode_sec` | да | секунды от начала видео, одна цифра после запятой; соглашение — в [TYPES.md](TYPES.md#таймкоды) |
| `violations[].description` | да | что видно на кадрах + почему это может указывать на нарушение, с пунктом нормы |
| `violations[].evidence_frames` | да | 1–3 кадра JPEG в base64; `timestamp_sec` — время кадра; первый или один из кадров — на таймкоде нарушения; область события обведена красной рамкой, таймкод подписан в углу |
| `violations[].type_id` | доп. | код типа: T1…T13, GENERIC |
| `violations[].rule` | доп. | `document`, `short`, `clause`, `url` (adilet.zan.kz с якорем пункта), `quote` (дословная цитата), `strength` (`прямая` / `косвенная`, см. [NORMS.md](NORMS.md)) |
| `violations[].confidence` | доп. | 0–1, заданная уверенность правила (0.4–0.75); это не откалиброванная вероятность |
| `meta` | доп. | `duration_sec`, `fps`, `frames_analyzed`, `processing_sec` (анализ), `stage_sec` (этапы), `models`, `job_processing_sec` (с ожиданием загрузки моделей) |
| `filename`, `created_at`, `processing_sec`, `video_duration_sec` | доп. | имя загруженного файла, время постановки (Unix), время обработки, длительность видео |

### GET /api/v1/health

```json
{"ok": true, "queue": 0, "workers": 2, "busy": 0, "analyzer": "real", "analyzer_state": "ready"}
```

- `queue` — задач в очереди, `busy` — обрабатывается сейчас, `workers` — параллельных потоков;
- `analyzer`: `real` — настоящий анализатор, `fake` — заглушка для проверки интерфейса;
- `analyzer_state`: `loading` (модели загружаются, задачи ждут), `ready`, `error` (задачи завершаются `failed` с причиной).

## Ошибки

Тело ошибки — `{"detail": "<текст на русском>"}`.

| Код | Когда |
|---|---|
| 401 | нет заголовка `X-API-Key` или ключ неверный |
| 400 | тело не `multipart/form-data`; нет поля `file`; расширение не .mov/.mp4/.m4v/.qt; пустой файл; ffprobe не читает видео, в нём нет видеопотока или ffmpeg не декодирует кадр в начале или в середине |
| 404 | неизвестный `job_id` |
| 413 | файл больше 200 МБ (`FORTE_MAX_UPLOAD_MB`) |

Ошибки самого анализа возвращаются не HTTP‑кодом, а статусом задачи `failed` с полем `error`.

## Как опрашивать

- Опрашивайте `GET /api/v1/jobs/{job_id}` раз в 2–5 с, пока `status` = `processing`. Веб‑интерфейс опрашивает раз в 1.5 с и повторяет через 3 с при сетевой ошибке (`service/static/app.js`).
- Время обработки на L40S при двух одновременных задачах (42 открытых ролика): медиана 25.7 с, ролики 12–26 с — 18–35 с, 72–73 с — 53–64 с, 143 с — 82.9 с ([ARCHITECTURE.md](ARCHITECTURE.md#время-обработки)). Шесть одновременных загрузок через публичный адрес (`FORTE_WORKERS=3`) получили результаты за 231 с. Под чужой нагрузкой на GPU одиночная задача может идти в несколько раз дольше. К этому добавляется ожидание в очереди (`queue_position`). Лимит жюри — 5 минут на видео.
- При сетевой ошибке или ответе 5xx на `GET` повторяйте запрос: задача продолжает выполняться на сервере, результат хранится на диске (`~/forte/jobs/<job_id>/`) и переживает перезапуск сервиса.
- Повторный `POST` того же видео создаёт новую задачу. Если `POST` оборвался до ответа, отправьте видео ещё раз.
- Таймаут клиента на `POST` — с запасом на загрузку файла: видео ТЗ около 29 МБ. Сервис принимает до 200 МБ (`FORTE_MAX_UPLOAD_MB`), прокси на постоянном адресе — до 210 МБ, резервный Cloudflare quick tunnel — до 100 МБ. Загрузка 29 МБ на постоянный адрес из Казахстана заняла 6–11 с.

```bash
JOB=$(curl -s -X POST "$URL/api/v1/analyze" -H "X-API-Key: $KEY" -F "file=@video.mov" | python3 -c 'import sys, json; print(json.load(sys.stdin)["job_id"])')
while :; do
  R=$(curl -s --retry 3 -H "X-API-Key: $KEY" "$URL/api/v1/jobs/$JOB")
  echo "$R" | grep -q '"status":"processing"' || break
  sleep 3
done
echo "$R" > result.json
```
