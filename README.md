# Контроль кассовой дисциплины по видео — ForteBank Datathon 26

Сервис принимает видеозапись кассы (.mov, камера сверху) и сообщает, видны ли на ней признаки возможных нарушений кассовой дисциплины. Для каждого найденного случая он выдаёт тип (T1–T13), таймкод, описание того, что видно на кадрах, 1–3 кадра‑доказательства и пункт нормативного акта РК. Детектор людей и локальная мультимодальная модель только описывают видео; решение «нарушение / нет» принимают явные правила (`pipeline/rules.py`), каждое из которых привязано к типу нарушения и пункту нормы (`pipeline/norms.json`). Результат — подсказка для проверки человеком, а не заключение.

## Адреса

- Веб‑интерфейс: https://216-81-248-201.sslip.io/ (ключ не нужен).
- API: https://216-81-248-201.sslip.io/api/v1, ключ в заголовке `X-API-Key`. Ключ команда передаёт жюри отдельно, в репозитории его нет.
  - `POST /api/v1/analyze` — загрузка видео (multipart, поле `file`, .mov или .mp4), ответ `{"job_id": ..., "status": "processing"}`;
  - `GET /api/v1/jobs/{job_id}` — статус и результат: `verdict`, `violations`, `meta`.

```bash
URL=https://216-81-248-201.sslip.io; KEY=<ключ>
curl -s "$URL/api/v1/health"
curl -X POST "$URL/api/v1/analyze" -H "X-API-Key: $KEY" -F "file=@video_017.mov"
# {"job_id":"99c7837d0400","status":"processing"}
curl -H "X-API-Key: $KEY" "$URL/api/v1/jobs/99c7837d0400"
# ... затем {"job_id":"99c7837d0400","status":"done","verdict":"violation","violations":[...],"meta":{...}}
```

Опрашивайте `GET /api/v1/jobs/{job_id}` раз в 2–5 с, пока `status` = `processing`. Полная схема ответа и коды ошибок — в [docs/API.md](docs/API.md).

## Результаты

Полный прогон того же кода, что работает в сервисе, на всех 42 открытых роликах (18.10.2026, 10:30). Эталон — разметка команды (`analysis/gt_team.json`): 26 роликов с нарушением, 16 чистых.

| Метрика | Значение |
|---|---|
| Верный вердикт по ролику | 41 из 42 (0.98) |
| Верный вердикт по меткам организатора | 37 из 42 (0.88) |
| Найдены ролики с нарушением | 25 из 26 |
| Ложные тревоги на чистых роликах | 0 из 16 |
| Тип нарушения совпал с разметкой | 25 из 26 |
| Таймкод в пределах 2 с от метки | 20 из 22, медиана ошибки 1.0 с |

Команда описала все 42 ролика словами. В X‑19, X‑35, X‑37 и X‑39 организатор отметил «без нарушения», а на видео кассир принимает деньги без проверки удостоверения. Сервис следует разметке команды; отсюда разница в строке «по меткам организатора».

**Скорость** (1 × NVIDIA L40S):

| Показатель | Значение |
|---|---|
| Ролик, медиана | 27.6 с |
| Самый длинный ролик (143 с видео) | 83.6 с |
| Все 42 ролика (1 447 с видео), по 2 задачи одновременно | 704 с |
| 6 видео одновременно через публичный адрес | все результаты за 231 с |

Лимит жюри — 5 минут на видео.

**Другой ракурс камеры.** 11 открытых роликов в 6 смоделированных ракурсах: перспектива, поворот, приближение, зеркало, затемнение, альбомный кадр. Итого 66 прогонов полного анализа: верный вердикт в 59, нарушение найдено в 46 из 48.

**Чего не находит** (подробно — [docs/LIMITATIONS.md](docs/LIMITATIONS.md)):

- X‑44: отбракованные купюры смешаны с годными. Карман отбраковки счётчика на этой камере занимает около 15 пикселей.
- T5 (ключ в замке сейфа) работает по узкому пиксельному признаку, а положительный пример в открытом наборе всего один.
- Пороги подобраны на тех же 42 роликах, отложенной выборки нет. На новых видео качество, скорее всего, ниже.

## Типы нарушений

Сервис распознаёт 13 типов, T1–T13. Для каждого есть пункт нормы РК с дословной цитатой, ссылки на adilet.zan.kz проверены. Подробно — [docs/TYPES.md](docs/TYPES.md) и [docs/NORMS.md](docs/NORMS.md).

| Код | Нарушение |
|---|---|
| T1 | Приём наличных без предъявления удостоверения личности |
| T2 | Деньги предыдущего клиента не убраны в сейф до обслуживания следующего |
| T3 | Наличные или сумка с деньгами оставлены на столе без присмотра |
| T4 | Сейф оставлен открытым |
| T5 | Ключ от сейфа оставлен в замке при уходе кассира |
| T6 | Ноутбук не выключен и не заблокирован при уходе кассира |
| T7 | Тетрадь или документы оставлены на столе при уходе кассира |
| T8 | Дверь кассы открыта во время работы с деньгами; посторонний у входа |
| T9 | В кабинете кассы больше двух человек |
| T10 | Не видно оформления приёма денег (выдаётся только вместе с T1 или T13) |
| T11 | Возврат купюр клиенту после пересчёта без видимого оформления акта |
| T12 | Личные вещи, еда или напитки на рабочем месте кассира |
| T13 | Не видно пересчёта и проверки купюр перед уборкой или объединением |

Модели только описывают видео. Решение «нарушение / нет» принимают явные правила, и каждое правило привязано к пункту нормы. В ответе сервис пишет, что видно на кадрах, и формулирует вывод как «может указывать на нарушение». Личность людей и подлинность купюр он не утверждает, лица не распознаются.

## Модели

- Qwen3‑VL‑8B‑Instruct (BF16) на локальном сервере vLLM: раскладка сцены, состояния объектов, факты по окнам кадров, проверки вокруг событий.
- YOLO26x (Ultralytics) — детекция людей, плюс собственный трекер: роли, вход и выход, больше двух человек в кабинете.

Всё работает локально на одном GPU‑хосте; облачные AI‑сервисы не используются. Интернет нужен только при установке (пакеты, веса).

## Структура репозитория

| Путь | Содержание |
|---|---|
| `pipeline/` | анализ видео: декодирование (`video.py`), люди (`persons.py`), состояния (`states.py`), факты (`vlm_facts.py`), проверки событий (`checks.py`), правила (`rules.py`), реестр типов и норм (`norms.json`), сборка результата (`analyze.py`); оценка на открытых роликах (`eval.py`, `batch.py`, `offline.py`) |
| `service/` | API и веб‑интерфейс (`app.py`, `static/`), режим‑заглушка (`fake.py`), systemd‑юниты, Caddyfile и скрипты развёртывания (`deploy/`) |
| `tools/` | установка и запуск сервера vLLM (`vllm_install.sh`, `vllm_serve.sh`), имитация нагрузки жюри (`jury_sim.sh`) |
| `analysis/gt_team.json` | разметка команды для 42 открытых роликов (для `pipeline.eval`) |
| `analysis/robust/` | проверка устойчивости к другому ракурсу: генерация ракурсов (`make_aug.py`) и подсчёт (`score.py`) |
| `docs/` | документация |
